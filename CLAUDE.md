This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Keystone UI is a Rails gem providing reusable UI components built on `view_component`. It provides UI primitives that avoid ERB noise, prevent UI drift, and enable safe mass updates.

## Commands

```bash
bundle install              # Install dependencies
bundle exec rake            # Run the component tests and the template rendering tests
bundle exec rake test       # Run the component tests
bundle exec rake test TEST=test/keystone/ui/button_component_test.rb  # Run a single test file
bundle exec rake test:render  # Run the template rendering tests
npm install                 # Install JavaScript test dependencies
npm test                    # Run the Stimulus controller tests
```

No build step or linter is configured.

## Architecture

This is a Rails engine gem structured around ViewComponent. The three-layer architecture is:

1. **Components** (`app/components/keystone/ui/`) — Ruby classes inheriting `ViewComponent::Base` with explicit keyword arguments, paired with `.html.erb` templates. All UI logic lives here.
2. **Helpers** (`app/helpers/keystone_ui_helper.rb`) — Thin render wrappers that delegate to components. Helpers contain no logic or conditionals. Consuming apps use helpers, not component classes directly.

Components use Tailwind CSS utility classes directly. At boot the engine writes `keystone_source.css` into the host through `KeystoneUi::SourceCss`: it imports keystone_ui-styles, points Tailwind at the component files, imports the color picker and grid safelist CSS, and adds whatever other gems registered in `KeystoneUi.configuration.tailwind_imports` and `tailwind_sources`. No file lives at `app/assets/tailwind/keystone_ui_engine/engine.css`, so tailwindcss-rails writes no generated stylesheet for keystone_ui. Host apps require `tailwindcss-rails` v4+.

## Design Principles

- All UI lives in ViewComponents (no partials).
- Components are Ruby objects with explicit keyword arguments.
- Helpers are thin render wrappers with no logic or conditionals.
- Styling uses Tailwind CSS utility classes applied directly in components.

## Testing

Ruby tests use Minitest. Stimulus controller tests live in `test/javascript` and run with Node's built-in test runner through `npm test`. The test helper stubs `ViewComponent::Base` so tests run without a full Rails environment. Those tests validate component logic (class composition, tag options, normalization) rather than rendered HTML.

Template rendering tests live in `test/render` and run through `rake test:render`, in a separate process from the rest. `test/render_helper.rb` boots a minimal Rails app with the real ViewComponent, and each test calls `render_inline` and reads the returned HTML with Nokogiri. A test that checks what a template outputs belongs there.

## Color System

Components use semantic CSS custom properties (`--color-accent-*`, `--color-surface-*`) via Tailwind classes like `bg-accent-500`, `text-accent-600`, etc. The keystone_ui-styles gem sets default values, defines light and dark mode, and holds the `ks-` classes the button, panel and form field components render. Host apps can override these via CSS, or use the `keystone_ui-colors` gem for per-user theming. Buttons, panels, cards, alerts, badges, form fields, the modal, the mobile action menu, the column picker, multi select, search select, copy button, theme toggle, checkbox row, radio card, option card, file upload, colour picker, the navigation components (navbar title, nav item, nav dropdown, bottom nav, mobile header and settings link) and the data display components (stat card, chart card, card link, CTA banner, feature grid, hero, data table, code, accordion, disclosure, tab switcher, progress, timeline, funnel, bucket, pipeline, swipe deck, stacked bar and status line) render keystone_ui-styles' `ks-` classes, which read `--ks-` variables for colour, radius, font, weight, shadow, border and spacing. Their constants keep only layout, size and behaviour utilities, so a look file that sets those variables restyles them. The README shows one.

## Key Conventions

- Ruby >= 3.1.0 required.
- Components live under the `Keystone::Ui` namespace.
- The DataTableComponent uses Tailwind CSS utility classes with predefined position-based class constants (first/middle/last cell styling). It accepts `items` (AR objects or hashes) and `columns` (simple `{ key: "Label" }` hashes or `Keystone::Ui::Column` objects), resolving cell values automatically. `Column` objects support per-column options: `mobile_hidden: true` (appends `hidden sm:table-cell` classes), `sortable: true` (renders header as clickable sort link), and `hideable: true` (allows hiding via `hidden_columns:`). A block-based API registers links via `table.link(:column_key) { |item| url }` and actions via `table.actions { |item| ... }`. `table.row_detail { |item| ... }` draws what it returns for an item in a `hidden` row under that item's row, one cell spanning every column with `data-row-detail-target="detail"` and an id from the item's `id` (or its position), and starts the row's first cell with a caret button carrying `aria-expanded="false"`, `aria-controls` and `data-row-detail-target="toggle"`; a `nil` return gives the row neither. With `row_detail` the `tbody` runs the `row-detail` Stimulus controller, which toggles on a click on the row unless the click was on another link, button or form control, and cancels `turbo:before-morph-attribute` for `hidden` and `aria-expanded` on its two targets so an open row stays open through a morph. When an actions column is present, position classes shift so the actions column gets LAST styling. Sortable columns accept `sort:`, `sort_direction:`, and `sort_url:` (a lambda) params — headers render as `<a>` links with arrow icons and `data-turbo-action="replace"`. Hidden columns are filtered server-side via the `hidden_columns:` param; only columns marked `hideable: true` can be hidden. `current_row:` takes an item, and the first row equal to it gets `CURRENT_ROW_CLASSES` (`ks-table-row-current`, coloured by keystone_ui-styles) and `aria-current="true"`; with no `current_row:` every row renders as a plain `<tr>`. `phone_list: true` shows the table as a list below `sm`: the heading row is hidden, the table, body and each row are blocks, each cell sits on its own line, starting at the left and wrapping, under a `ks-caption` label holding its column's heading that is hidden from `sm` up, and each subtotal in a group heading row and each total after the first carries its column's heading the same way. Every class it adds is a `max-sm:` class or part of that label, so from `sm` up the table looks as it does without it, and a table that does not pass it looks the same at every width. Links, badges, the detail button and the action menu stay in each row's list item, saved column layouts and `mobile_hidden:` columns apply as in the table, and below `sm` a chosen table has no sort links, since they sit in the hidden heading row. `header: false` renders no `thead`, and with `phone_list: true` gives no cell, subtotal or total its `ks-caption` heading label. `actions?` is true only when the `actions` block, captured once per row, renders something for at least one row, so a block that renders nothing for every row adds no actions column and leaves the last data column with LAST styling.
- ColumnPickerComponent renders a "Columns" dropdown with checkboxes for each `hideable` column. It accepts `columns:`, `hidden_columns:`, and `save_url:`. The Stimulus `column-picker` controller handles toggle/close and PATCHes hidden column preferences to `save_url` as JSON, then reloads via `Turbo.visit`.
- GridComponent uses a `COL_CLASSES` frozen hash mapping `{breakpoint => {count => "literal-class"}}` for cols 1-12 across `default`, `sm`, `md`, `lg`, `xl` breakpoints. `wide: :first` or `wide: :second` swaps each breakpoint's two-column class for `WIDE_COL_CLASSES`' literal `grid-cols-[minmax(0,3fr)_minmax(0,2fr)]` or `grid-cols-[minmax(0,2fr)_minmax(0,3fr)]` with that breakpoint's prefix, and `grid_safelist.css` lists every one. All Tailwind classes are complete static strings (never interpolated) so the JIT scanner can detect them. Gap classes use the same pattern via `GAP_CLASSES`, `GAP_X_CLASSES`, and `GAP_Y_CLASSES` constants.
- ButtonComponent conditionally renders `<a>` or `<button>` based on whether `href` is provided. With `href` and a `method:` other than `:get`, it renders a `button_to` form that sends that method, as ActionMenuItemComponent does. `full_width: true` adds `w-full` to the button and to that form. `variant: :text` replaces the button classes with keystone_ui-styles' `ks-text-button` class. Without `href`, `name:` and `value:` become the button's attributes, `hidden: true` adds the `hidden` attribute, and `disabled: true` adds the `disabled` attribute. Without `href`, `formaction:` becomes the button's `formaction` attribute, so pressing it sends its form to that address.
- ButtonRowComponent (`ui_button_row`) draws its block in a `flex flex-wrap ks-grid-gap-sm` row whose direct children get `min-h-11` below `sm`, and whose `form` children, the forms `button_to` draws, are `flex` with their button `flex-1`. `equal_width: true` adds `*:flex-1 *:whitespace-nowrap`, so each child takes an equal share and the row wraps only when a label no longer fits, and `equal_width: :phone` adds the same two classes with `max-sm:`. `class:` adds its classes to the row, as DecisionBarComponent does to pick the breakpoint its row's equal shares stop at.
- ReviewCardComponent (`ui_review_card(id:, title:, score: nil, score_tone: :muted, body: nil, cta: nil, meta: nil, finding: nil, actions: [], compact: false)`) draws an `article` in `CARD_CLASSES` (`ks-card ks-panel-padding-sm flex flex-col ks-grid-gap-sm`, with `sm:[&_.ks-button]:min-w-0 sm:[&_.ks-button]:text-xs` so three buttons take equal shares in a third of the page). Its header line is a `justify-between ks-grid-gap-sm` row of the `id:` in `font-mono ks-tone-muted` and the `score:` in the `TONE_CLASSES` entry for `score_tone:`, which holds `ks-tone-muted` and a `ks-tone-<state>` class for each name in `States::NAMES`, the list BadgeComponent and StatusDotComponent build theirs from. Under it come the `title:` in `ks-card-title`, the `body:` in `ks-card-summary`, the `cta:` as text in `ks-card-link`, the `meta:` in keystone_ui-styles' `ks-card-meta` (a top border and padding) with `font-mono`, the `finding:` in `ks-alert ks-alert-warning`, and the `actions:` as small secondary ButtonComponents in a ButtonRowComponent with `equal_width: true`. A `finding:` adds keystone_ui-styles' `ks-card-warning` to the article. `compact: true` adds `COMPACT_BODY_CLASSES` (`truncate`) to the body, cutting it to one line with an ellipsis, and leaves out the call-to-action line and the meta line. Its buttons are joined with a space, so the card's text reads each label as its own word.
- ReviewCardGridComponent (`ui_review_card_grid`) draws its block in a GridComponent with `cols: { default: 1, lg: 3 }` and `gap: :sm`.
- LinkComponent (`ui_link`) renders `label:` as a link to `href:` with keystone_ui-styles' `ks-link` class. `centred: true` uses `CENTRED_CLASSES` (`ks-link block text-center`), so the link takes its own line with its label in the middle.
- ChipRowComponent (`ui_chip_row(chips:)`) draws a `ROW_CLASSES` div (keystone_ui-styles' `ks-chip-row`, with `max-sm:grid max-sm:grid-cols-3` so a phone shows three chips across and a fourth starts a new line) of one span per chip in its `TONE_CLASSES` entry (`ks-chip ks-chip-<tone>`, one for each name in `States::NAMES`, looked up with `fetch`). Each chip holds its `label:` and `value:` as two spans, and `mono: true` gives the value span `font-mono`.
- FigureComponent (`ui_figure`) takes `tone:` `:neutral`, `:success`, `:danger`, `:warning` or `:info`, the last four adding the matching `ks-tone-` class.
- Small-capital options add keystone_ui-styles' `ks-label-caps`, which sets size, weight, case, letter spacing and colour: StatCardComponent's `label_caps: true` uses `CAPS_LABEL_CLASSES` (`ks-stat-card-label ks-label-caps`, with no size utility, since a utility would win over the style's size), DataTableComponent's `heading_caps: true` swaps each column heading's `text-sm` for `HEADING_CAPS_CLASSES`, and ValueListComponent's `label_caps: true` adds `CAPS_LABEL_CLASSES` to each label.
- DataTableComponent's `density: :compact` swaps `text-sm` for `text-xs` on every heading and cell and adds keystone_ui-styles' `ks-table-compact` (`COMPACT_CLASSES`) after each one's own header or cell class, so its padding wins; with `heading_caps: true` the heading keeps `ks-label-caps` and gets no `text-xs`.
- Fixed-width options add `font-mono`: ValueListComponent's `value_mono: true` uses `MONO_VALUE_CLASSES` on each value, and TimelineComponent's `text_mono: true` adds `MONO_CLASSES` to each duration and to each step name, which in the default layout uses `MONO_LABEL_CLASSES` (`min-w-0 wrap-break-word font-mono`) so a long name wraps inside its row.
- FactsComponent (`ui_facts`) renders `facts:`, an array of `{ value:, label: }` hashes, as `ks-fact` spans in a `ks-facts flex flex-wrap` row, each value in a `b` with `ks-tone-neutral` before its label.
- CaptionComponent (`ui_caption`) takes `tone:`, `:muted` by default, and `:link` adds keystone_ui-styles' `ks-caption-link` class. `normal_case: true` adds keystone_ui-styles' `ks-caption-normal-case` class, and a block given to it, which the helper passes on, is drawn in place of `text:`, so the line can hold links.
- StatCardComponent (`ui_stat_card`) with `compact: true` uses `COMPACT_CLASSES` (keystone_ui-styles' `ks-metric-card ks-metric-card-compact`), a `text-xs` label and `COMPACT_VALUE_CLASSES` (`ks-stat-card-value-compact` in a `flex flex-wrap items-baseline` row at `text-lg leading-6`), draws its change and note as `text-xs` spans inside that row, and draws no change row under it. Its `VARIANT_CLASSES` are built from `States::NAMES`, one `ks-tone-<state>` class each, as BadgeComponent builds its own.
- PageHeaderComponent (`ui_page_header`) with `subtitle_mono: true` draws its subtitle in `MONO_SUBTITLE_CLASSES` (`ks-page-header-subtitle font-mono`).
- ValueListComponent (`ui_value_list`) adds `KEY_ROW_CLASSES` (`ks-value-list-key`) to a row given `key: true`, which keystone_ui-styles draws larger than the others without the weight of a total.
- ValueListComponent (`ui_value_list`) draws a green check mark SVG with `aria-label="Right"` and `ks-tone-success` after the value of a row given `right: true`.
- ValueListComponent (`ui_value_list`) given `columns: true` draws each pair as a `flex flex-col min-w-0` stack with its label in `text-xs`, inside a `grid grid-cols-1 sm:grid-cols-2 ks-grid-gap-sm` list, and leaves out the `ks-value-list-row` class so the pairs carry no border between them.
- SectionComponent (`ui_section`) draws its `aside` slot in the header after the title block, in a `ks-heading-note ml-auto wrap-normal sm:shrink-0 max-sm:basis-full max-sm:order-last` element, so it never breaks mid-word and keeps its full width from `sm` up while the title block, which carries `min-w-0`, wraps, so it sits at the right end of the title line before the action and the menu, and below `sm` takes a line of its own after the title and the actions. A header with an aside carries `ks-grid-gap-sm max-sm:flex-wrap` as well as `ks-section-header`, and a header without one carries only `ks-section-header`. An aside given with no `title:` raises `ArgumentError`, since the header that holds it renders only with a title.
- HeroComponent (`ui_hero`) takes `title_size:`, `:lg` by default, and `:sm` draws the title at `text-3xl md:text-4xl`.
- PictureComponent (`ui_picture`) renders an `<img>` with `src:` and `alt:`, centred and held to `max-h-[50svh]` so it is never taller than half the visible screen. With `full_size_url:` it is wrapped in a link opening that address in a new tab.
- NavbarComponent is the top-level navigation bar with slots for `logo`, `desktop_links`, `desktop_right`, `mobile_left`, `mobile_center`, and `mobile_right`. Supports `sticky: true` (default) for fixed positioning. Mobile sections are hidden on `lg:` screens and vice versa. `hide_logo_on_mobile: true` hides the `logo` slot below `lg:` for a page that shows its own title in the mobile header.
- NavDropdownComponent renders a dropdown menu within the navbar. Accepts `title`, `area`, and `active` flag. Uses Stimulus `dropdown` controller for toggle behavior. The title sits in a `min-w-0 truncate` span inside the trigger, so a long page title in the phone top bar ends in an ellipsis instead of widening the page.
- NavigationComponent (`ui_navigation`) draws the groups declared with `KeystoneUi.configuration.navigation_group` as NavDropdownComponent menus of NavItemComponent tabs in a NavbarComponent, inside a `hidden lg:block` sticky wrapper, then the page content passed as a block, both inside one plain `div` with no classes so the bar stays sticky for the whole height of the content. Its `logo` slot is drawn through the navbar's `logo` slot and its `menus` slot through the navbar's `desktop_right` slot, both set inside that block, and the top bar draws neither when the layout sets neither. `KeystoneUi.configuration.navigation_tab` declares a tab outside any group as a `NavigationGroup` of one tab flagged `standalone?` and labelled with the tab's label, which the top bar draws as a NavItemComponent with no dropdown and the sidebar as a `ks-sidebar-tab` link with no group label, no `<details>` and no `ks-sidebar-group-tabs` element. `KeystoneUi::NavigationGroup` holds a group's label and tabs, and each tab's key, label, `href` (an address or a callable given the view) and `permitted` callable given the view, and an optional `count` callable given the view, whose result above zero both placements show in an info BadgeComponent after the tab's label. A tab whose `permitted` returns false is left out, a group with no tab left is left out, and with no group left it draws only the content unless the layout set a logo or menus, in which case the top bar holds just those. It asks `KeystoneUi.configuration.supplied_preference` for `:navigation`, and when the value's `"placement"` is `"left"` or `"right"` it draws a `ks-sidebar` panel instead of the top bar, hidden below `lg:`, on that side of the content in a row that is side by side from `lg:` up. The panel holds the logo, then each group's `ks-sidebar-group-label` above one `ks-sidebar-group-tabs` element holding its `ks-sidebar-tab` links, so keystone_ui-styles can draw a border around them and lines between them, then the menus pushed to its bottom, in a wrapper whose arbitrary-variant utilities make every `[data-dropdown-target=menu]` inside it `static` and `basis-full` and every `[data-controller~=dropdown]` inside it `flex-wrap`, so a menu's panel opens on its own line below its button inside the sidebar, even one the host positions absolutely in a stylesheet layered below Tailwind's utilities. A panel that also has the `hidden` class is made `block`, `h-0`, `overflow-hidden`, `my-0`, `py-0` and `invisible`, so a closed menu still counts toward the sidebar's width without taking height, focus or a place in the accessibility tree, and opening it never changes the sidebar's width. The top bar's menus get no such wrapper and open as the host draws them. `KeystoneUi::NavigationOrder` arranges the visible groups and their tabs in the order listed under the value's `"order"`, a list of `{ "group" => label, "tabs" => [tab key strings] }` entries, in either placement: unnamed groups and tabs follow the named ones in declared order, and names no longer declared are ignored. It asks `KeystoneUi.configuration.supplied_current_tab`, which calls `current_tab_supplier` with the view, for the key of the tab the page belongs to, and marks that tab and its group active: the nav item and nav dropdown's `active:` flag in the top bar, and the `active` class on the `ks-sidebar-tab` and its group's `ks-sidebar-group-label` in the sidebar. A `nil` key, a key no visible tab has, or no supplier marks nothing. `KeystoneUi::VisibleNavigation` builds the one list both placements draw: the visible groups in the saved order, each with its label, its visible tabs and whether it holds the current tab, and each tab with its label, its link for the view and whether it is the current tab. `KeystoneUi::NavigationCheck`, run by the engine in `after_initialize` through `KeystoneUi::Engine.check_navigation`, raises `KeystoneUi::NavigationCheck::Error` when a declared group has no tabs, a tab has no label or no `href`, or two tabs share a key, naming the group, the tab or the key.
- NavItemComponent is a single nav link with `label`, `href`, and `active` state.
- BottomNavComponent renders a mobile bottom tab bar, hidden on desktop (`lg:hidden`).
- BottomNavItemComponent is a single bottom nav tab with `label`, `href`, `icon` (SVG string), `active` state and an optional `count`, whose value above zero shows in an info BadgeComponent placed over the icon.
- TabSwitcherComponent (`ui_tab_switcher`) takes label strings switched in the browser, or link tabs `{ label:, href:, current:, count: }`. A count above zero is drawn after the label in an info BadgeComponent, as NavItemComponent draws its count, and a tab given `show_zero: true` draws a count of zero too. `align: :start` starts the row at the left edge on every width instead of centring it from `sm` up. `id:` puts an `id` on the tab row, the `nav` of link tabs or the `div` of label tab buttons, so a Turbo Stream can replace the row, and a link tab switcher rendered with no block draws only that row. `shape: :pills` or `shape: :underline` adds keystone_ui-styles' `ks-tab-bar-pills` or `ks-tab-bar-underline` to the row, drops `text-sm` from the tabs so the shape sets their size, and draws a count as a plain `ks-tab-count` span. Below `sm` every row stays on one line and scrolls sideways. Label tabs take a `panels` slot, one `with_panel` per tab, each drawn as a `min-w-0` `fieldset` with `data-tab-switcher-target="panel"`; every panel after the first starts `hidden` and `disabled`, and the `tab-switcher` controller's `select` sets `hidden` and `disabled` on every panel but the chosen one, so fields keep their values and a hidden panel's fields neither block nor join the form.
- MobileHeaderComponent (`ui_mobile_header(title:, back_url:, subtitle: nil, overline: nil, badge: nil)`) renders a mobile header with back link, title, and optional subtitle, overline and badge. Hidden on `lg:` screens. With no `back_url` it draws no back-link wrapper, so no gap is left before the title. The `overline` is a line of small muted text inside the title element, above the title, using the subtitle's `ks-mobile-header-subtitle` class and cut off with an ellipsis. The `badge` hash is passed to BadgeComponent and drawn after the title with `ml-auto shrink-0 self-center`, so it sits at the right end of the header's row, or of the space before NavbarComponent's `mobile_right` controls, at its full width and its own height while the title shrinks. With a `nil` `back_url` it renders no back link. It renders the back link and the title in one row with keystone_ui-styles' `ks-page` class, so placed outside a top bar it has the same side margin as PageComponent. Below `lg:` inside a `.top-nav` element that row is `display: contents`, and the title is a flex item that takes the space left in the bar's row, with its text starting at the left and cut off with an ellipsis, so a hand-written bar must be a flex row with the `top-nav` class and the header as its direct child. NavbarComponent's `mobile_left` slot does that with `display: contents` when it holds the header's title, its `nav` then wraps so controls with no room move to a second row, and its `mobile_right` slot wraps its controls, all from `max-lg:` variants that check for `.ks-mobile-header-title`, so a page with no header and every width from `lg:` up are unaffected.
- MobileActionsComponent renders an ellipsis dropdown for mobile action menus. Hidden on `lg:` screens. Uses the Stimulus `action-menu` controller, as ActionMenuComponent does: the menu opens under its button, above it when there is no room below, moves with its button while the page scrolls, and closes on a pointer released outside it or a resize.
- MobileActionComponent (`ui_mobile_action`) draws the action `ui_page_header(action_url:, action_label:)` publishes as a plus icon link for a host's top bar. When the page header also publishes `action_method:` as `:mobile_action_method`, it draws the icon as a `button_to` form sending that method, with the same classes and aria label, and a published `:mobile_action_confirm` becomes that form's `data-turbo-confirm`. It draws nothing with no published action, and it is hidden from `sm:` up, inside a Hotwire Native web view and in print.
- BottomActionComponent (`ui_bottom_action`) draws the action `ui_page_header` publishes as a full-width ButtonComponent inside keystone_ui-styles' `ks-bottom-action` bar, which is fixed to the bottom of the screen and sits above the bottom nav on a page that has one. It sends `:mobile_action_method` when published and asks `:mobile_action_confirm`, which `ui_page_header(action_confirm:)` publishes, before sending, draws nothing with no published action, and is hidden from `sm:` up, inside a Hotwire Native web view and in print. After the bar it draws an inert wrapper holding an invisible copy of the bar in the page's flow and a block as tall as `--ks-bottom-nav-height` shown only when the page has a bottom nav, so the page's last content can scroll clear of both.
- DecisionBarComponent (`ui_decision_bar(url:, primary:, actions: [], note: nil, hint: nil, method: :post)`) draws one `form_with` form in `FORM_CLASSES`, a `ks-panel` flex row that wraps and is `max-sm:contents`. Inside it a `ks-bottom-action` div in `BAR_CLASSES` holds the note field, a ButtonRowComponent with `equal_width: :phone` of the `actions:` as secondary ButtonComponents, and the `primary:` ButtonComponent in a div in `PRIMARY_CLASSES` (`max-sm:order-first max-sm:*:w-full max-sm:*:min-h-12`). From `sm:` that div is `contents`, so its children sit in the form's row, and below `sm:` it is the fixed bottom bar laid out as a column. `primary:` and each action are ButtonComponent keywords. Each action is drawn in a div in `ACTION_CLASSES` (`flex *:flex-1`), so the row's phone classes size the div and the button fills it. An action's `phone_only: true` adds `PHONE_ONLY_CLASSES` (`sm:hidden`) to that div and its `phone_order:` (1 to 3) adds the matching `PHONE_ORDER_CLASSES` entry (`max-sm:order-N`), looked up with `fetch` so any other value raises `KeyError`. An action with `href:` and a `method:` other than `:get` is drawn as a button with ButtonComponent's `formaction:` set to its `href:` and `name="_method"` set to its method, so pressing it sends the bar's form to its own address with that method while the other buttons send the form to `url:` unchanged. Such an action given its own `name:` or `value:` raises `ArgumentError`. Each action's div also carries the `PHONE_ACTION_TEXT_CLASSES` entry for the breakpoint (`max-sm:*:text-sm`), so below it the secondary buttons' labels are small text and a label such as "Send back" stays on one line three across at 390px. Its `phone_label:` makes the button's label two spans, `label:` in `FULL_LABEL_CLASSES` (`max-sm:hidden`) and `phone_label:` in `PHONE_LABEL_CLASSES` (`sm:hidden`). `note:` takes `name:`, `label:` and `placeholder:` and draws an InputComponent inside a `label` in `NOTE_CLASSES`, and `hint:` draws a `ks-hint` paragraph on its own line, both `max-sm:hidden`. `breakpoint:` (`:sm` by default, `:md` or `:lg`) picks the width it switches forms at: every phone-form and desktop-form class is held in a hash keyed by breakpoint, with literal `max-sm:`/`sm:`, `max-md:`/`md:` or `max-lg:`/`lg:` strings. Its secondary buttons sit in a ButtonRowComponent given `SECONDARY_ROW_CLASSES` for that breakpoint, so each takes an equal share with `min-w-0`, and `ACTION_CLASSES` lets each button shrink and wrap its label with `wrap-break-word`. The bar carries `hotwire-native:bottom-0`, since the bottom nav is hidden in a Hotwire Native web view, and is not hidden there. After the form it draws an inert, `sm:hidden` wrapper holding an invisible `!static` copy of the bar's buttons and a block as tall as `--ks-bottom-nav-height` shown only when the page has a bottom nav and is not in a Hotwire Native web view.
- TimelineComponent (`ui_timeline(entries:)`) groups entries by `label:` into rows and places each bar on one axis. An entry's `href:` makes its bar an `<a>` holding its label in an `sr-only` span, and the row's label is an `<a>` to the last `href:` in the row.
